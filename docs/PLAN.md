# Kapchyk: план разработки

> **Kapchyk** (кырг. «капчык», то есть кошелёк) — мультивалютный кошелёк для портфолио Flutter-разработчика.
> Название продолжает кыргызскую линию портфолио (Joldosh).

Статус: **черновик, ждёт «ок»**.

## 2. Продукт

| Раздел     | Что умеет                                                                                                                                       |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Онбординг  | Слайды, создание и подтверждение PIN, включение биометрии                                                                                     |
| Вход       | PIN или биометрия, лимит попыток, автоблокировка после сворачивания, заглушка в списке задач                                                     |
| Счета      | Общий баланс в базовой валюте, карточки счетов (KGS, USD, EUR, RUB, KZT), скрытие балансов, детали счёта                                       |
| Переводы   | Между своими счетами (с конвертацией) и по номеру телефона: форма → подтверждение → результат, понятные ошибки, повтор                              |
| История    | Бесконечная лента, поиск, фильтры по дате, типу и категории, офлайн-кеш, детали операции                                                       |
| Аналитика  | Расходы по категориям за период: кольцевая диаграмма, доли, динамика по месяцам                                                                 |
| Курсы      | Курсы из реального публичного API, конвертер, офлайн показываются последние сохранённые курсы                                                    |
| Настройки  | Тема (системная / светлая / тёмная), язык (RU / EN), смена PIN, биометрия, сброс приложения                                                       |

Каждый экран умеет loading / empty / error, работает в светлой и тёмной теме, на RU и EN, на телефоне и планшете.

## 3. Архитектура

```
lib/
  app/        bootstrap, DI, роутер, тема, корневой виджет
  core/       общая инфраструктура: ошибки, Result, сеть, хранилища, БД,
              fake backend, деньги и валюты, общие виджеты
  features/
    auth/  settings/  exchange_rates/  accounts/
    transactions/  transfers/  analytics/
      data/          DTO, мапперы, data sources, реализации репозиториев
      domain/        entities, интерфейсы репозиториев, use cases (чистый Dart)
      presentation/  bloc/cubit, экраны, виджеты
  l10n/       ARB-файлы RU/EN
```

**Правила зависимостей**

- `presentation → domain ← data`. Domain — чистый Dart: ни Flutter, ни JSON, ни dio, ни drift.
- Фича может импортировать только `domain` другой фичи. Чужие `data` и `presentation` под запретом.
- DTO существуют только в `data`. Наружу из репозитория выходят только entity.

**Ошибки**

```
DataSource бросает типизированное исключение (NetworkException, ServerException(code), CacheException…)
  → Repository ловит и возвращает Result<T>: Ok(value) | Err(Failure)
    → Bloc разбирает sealed Failure через pattern matching и кладёт его в состояние
      → Виджет переводит Failure в локализованный текст
```

До UI исключения не доходят. Неожиданные ошибки ловят `PlatformDispatcher.onError`, `FlutterError.onError` и BlocObserver.

**Fake backend**

- `FakeBankServer` хранит в памяти состояние «сервера»: счета, операции, получателей по телефону. Демо-данные генерируются детерминированно, примерно за 6 месяцев.
- `FakeNetwork` добавляет задержку 300–1500 мс и случайные ошибки. Их доля задаётся через `--dart-define=FAKE_FAILURE_RATE`, в тестах Random детерминированный.
- В каждой фиче `Fake*RemoteDataSource implements *RemoteDataSource`. Он отдаёт DTO через `fromJson`, так что весь путь JSON → DTO → маппер → entity работает как с настоящим API. Бросает те же исключения, что бросал бы клиент на dio.
- Чтобы перейти на реальный API, нужна новая реализация `*RemoteDataSource` на dio и её регистрация в DI для окружения `prod`. Domain и presentation при этом не меняются.

**Деньги**

`Money(int minorUnits, Currency)`. Суммы никогда не хранятся в `double`. Курсы хранятся в `Decimal`, при конвертации округление half-even до копеек валюты.

## 4. Стек (предварительно)

Окончательный выбор, альтернативы и причины фиксирую в `docs/DECISIONS.md` по мере работы.

| Задача                 | Выбор                                                     | Коротко почему                                                                                                       |
| ---------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Состояние              | flutter_bloc + bloc_concurrency                           | Требование; `restartable` + debounce для поиска, `droppable` для догрузки страниц                                    |
| DI                     | get_it + injectable                                       | Требование; окружения `mock` и `prod` для подмены backend                                                           |
| Навигация              | go_router                                                 | Требование; `StatefulShellRoute` для вкладок, `redirect` для онбординга                                             |
| Сеть                   | dio + интерцепторы                                        | API-ключ из `--dart-define`, логи только в debug, retry с backoff для GET, перевод DioException в типизированные исключения |
| DTO                    | json_serializable                                         | Требование                                                                                                          |
| Локальная БД           | **drift** (SQLite)                                        | Фильтры, поиск и keyset-пагинация истории естественно ложатся на SQL. В тестах in-memory БД, есть миграции            |
| Секреты                | flutter_secure_storage                                    | Хеш PIN с солью, счётчик попыток, флаг биометрии                                                                    |
| Настройки              | shared_preferences                                        | Тема и язык не секрет                                                                                               |
| Биометрия              | local_auth                                                | Требование                                                                                                          |
| Графики                | fl_chart                                                  | Самый зрелый пакет графиков для Flutter                                                                               |
| Модели состояний       | sealed-классы Dart 3 + equatable                          | Без freezed: меньше кодогенерации, pattern matching есть в языке                                                    |
| Результат операций     | свой sealed `Result<T>`                                   | Так сделано в официальном Flutter architecture guide; без fpdart и dartz                                              |
| Локализация            | flutter gen-l10n (ARB)                                    | Стандартный инструмент                                                                                                 |
| Тесты                  | flutter_test, bloc_test, mocktail                         | mocktail не требует кодогенерации                                                                                   |
| Линтер                 | very_good_analysis, `flutter analyze --fatal-infos`       | Один из самых строгих наборов правил                                                                                 |
| Мелочи                 | intl, decimal, uuid, clock                                | Форматы, точные курсы, idempotency-key, время, которое можно подменить в тестах                                      |
| API курсов             | ExchangeRate-API (`open.er-api.com`)                      | Работает без ключа и знает KGS, KZT, RUB. Если передан `--dart-define=EXCHANGE_RATE_API_KEY`, используется эндпоинт с ключом и бо́льшими лимитами. У Frankfurter (ЕЦБ) нет KGS, у НБКР XML и мало валют |
| Сгенерированный код    | Не коммитим (`*.g.dart`, `*.config.dart`)                  | Нет шума в диффах; CI запускает `build_runner` сам                                                                   |

## 5. Фазы

Внутри фазы работаю автономно. В конце каждой фазы останавливаюсь и отчитываюсь.

### Фаза 0. Setup

- Репозиторий (см. вопрос 1 в разделе 7), `.fvmrc`, `flutter create` для android и ios, applicationId `io.github.kkairatik.kapchyk`.
- very_good_analysis; `analysis_options.yaml` исключает сгенерированные файлы; `.gitignore` для `.fvm/`, `*.g.dart`, `key.properties`, `*.jks`, `.env*`.
- Каркас папок, базовые зависимости.
- `docs/PLAN.md`, `docs/DECISIONS.md`, `docs/LEARN.md`, а также **CLAUDE.md** с правилами проекта для следующих сессий.
- **Минимальный CI сразу** (format + analyze + test). Это раньше твоего порядка, но поломки дешевле ловить с первого коммита. Сборку APK и порог покрытия добавлю в фазе 10.
- Прочитать release notes Flutter 3.38–3.47 и Dart 3.10–3.13: что изменилось и что устарело.

### Фаза 1. Core

- `bootstrap`: обработчики ошибок, BlocObserver, инициализация DI.
- `Env`: чтение `--dart-define` (`BACKEND`, `FAKE_FAILURE_RATE`, `EXCHANGE_RATE_API_KEY`). Секретов в коде нет.
- Исключения, sealed `Failure`, `Result<T>`, общий хелпер репозиториев для перевода исключений в Failure.
- Фабрика Dio и интерцепторы.
- Обёртки над secure storage и shared_preferences за интерфейсами, чтобы их было легко мокать. `AppDatabase` на drift.
- Fake backend: `FakeBankServer`, `FakeNetwork`, генератор демо-данных.
- `Currency`, `Money`, форматирование через intl.
- UI-база: тема Material 3 (светлая и тёмная, seed-цвет, `ThemeExtension` для цветов дохода и расхода), gen-l10n RU/EN, go_router с оболочкой вкладок и экранами-заглушками, адаптивный каркас (`NavigationBar` до 600dp, `NavigationRail` от 600dp), общие `LoadingView`, `EmptyView`, `ErrorView` с кнопкой повтора.
- Тесты: Money, Result, интерцепторы, перевод DioException в исключения, FakeNetwork.

### Фаза 2. Auth: онбординг, PIN, биометрия, автоблокировка

- Онбординг: слайды → создание PIN → подтверждение → предложение включить биометрию.
- PIN не хранится в открытом виде: в secure storage лежит хеш PBKDF2 с солью. После 5 ошибок вход блокируется, время блокировки растёт.
- Экран входа: своя цифровая клавиатура, биометрия запускается сама, при отказе остаётся PIN.
- Автоблокировка через `AppLifecycleListener`. При сворачивании показывается заглушка, чтобы балансы не были видны в списке задач. Если приложение было свёрнуто дольше grace-периода, оно блокируется.
- Экран блокировки — оверлей над навигатором, а не маршрут. Так не теряется состояние, например недозаполненный перевод. В DECISIONS сравню с вариантом через `redirect`.
- `redirect` в go_router: если PIN ещё не создан, ведёт на онбординг.
- Тесты: use cases (SetupPin, VerifyPin с попытками, биометрия), репозиторий с моком secure storage, bloc_test, widget-тест клавиатуры PIN.

### Фаза 3. Настройки

- Тема и язык применяются сразу и сохраняются.
- Смена PIN (старый → новый → подтверждение), включение и выключение биометрии, сброс приложения (стирает секреты и кеш).
- Фаза стоит так рано, чтобы каждый следующий экран я сразу проверял в тёмной теме и на EN.
- Тесты: SettingsCubit, use case ChangePin, репозиторий.

### Фаза 4. Курсы валют и конвертер

- Реальный API через Dio: DTO → маппер → entity `ExchangeRates`.
- Последние курсы кешируются в drift. Офлайн показываются сохранённые с пометкой «обновлено N назад».
- Экран курсов: pull-to-refresh, поиск валюты. Конвертер: две валюты, кнопка «поменять местами», расчёт на лету.
- Тесты: маппер на реальном образце JSON; репозиторий в трёх сценариях (сеть работает; сеть упала, есть кеш; кеша нет → Failure); use case ConvertCurrency; bloc_test.

### Фаза 5. Счета

- Главная: общий баланс в базовой валюте (пересчёт по курсам из фазы 4), карточки счетов, кнопка «скрыть балансы».
- Детали счёта: баланс, реквизиты (номер замаскирован, можно скопировать), действия.
- Fake API: `GET /accounts`, `GET /accounts/{id}`. Счета кешируются в drift.
- Тесты: мапперы, репозиторий, use case GetTotalBalance, bloc_test, widget-тест карточки.

### Фаза 6. История операций

- Keyset-пагинация по (`bookedAt`, `id`): новые операции не создают дублей, в отличие от offset. Бесконечный скролл и pull-to-refresh.
- Поиск с debounce. Фильтры: период (DateRangePicker), тип (доход, расход, перевод), категории (мультивыбор).
- Офлайн-кеш по схеме network-first: успешные страницы пишутся в drift, без сети тот же запрос выполняется локально в SQL, сверху баннер «офлайн, данные на …».
- Группировка по дням, экран деталей операции, последние операции на экране счёта.
- Тесты: репозиторий онлайн и офлайн, DAO на in-memory drift (фильтры, поиск, пагинация), HistoryBloc (загрузка, догрузка, поиск, фильтры, ошибки), widget-тест состояний.

### Фаза 7. Переводы

- Между своими счетами (с конвертацией и показом курса) и по номеру телефона: маска, валидация, поиск получателя (показывается «Айбек К.»).
- Флоу: форма → подтверждение (сумма, комиссия, итог, курс) → обработка → результат: успех с чеком или понятная ошибка с кнопкой повтора.
- Валидация: сумма больше 0, не больше баланса, в пределах лимитов, знаков после запятой не больше, чем у валюты. Ошибки полей и ошибки сервера показываются по-разному.
- Обрабатываемые ошибки: недостаточно средств, получатель не найден, превышен лимит, таймаут, нет сети.
- У каждой попытки перевода свой **Idempotency-Key**. Повтор после таймаута не спишет деньги дважды, fake-сервер это соблюдает.
- Bloc флоу живёт в ShellRoute переводов: он общий для всех шагов и уничтожается при выходе из флоу.
- Тесты: валидаторы, use cases (GetQuote, CreateTransfer), fake-сервер (идемпотентность, балансы), TransferBloc, widget-тест формы.

### Фаза 8. Аналитика

- Расходы по категориям за месяц: кольцевая диаграмма и список с долями; столбцы по месяцам; переключение периода.
- Агрегация — чистая функция в domain с пересчётом в базовую валюту.
- Тесты: use case агрегации, bloc_test, widget-тест пустого периода.

### Фаза 9. Полировка

- Проверка каждого экрана: loading, empty, error, тёмная тема, EN, шрифт 200%, телефон, планшет, landscape.
- На широких экранах история и счета показываются в две панели: список и детали.
- Доступность (Semantics, размер тап-зон), анимации переходов, иконка, splash.
- Опционально, если решим вместе: шифрование БД (SQLCipher), `FLAG_SECURE`.

### Фаза 10. CI и README

- GitHub Actions: версия Flutter из `.fvmrc`, кеш pub, `dart format --set-exit-if-changed`, `flutter analyze --fatal-infos`, `flutter test --coverage`, порог покрытия domain + data не ниже 70% (свой скрипт в `tool/`), `flutter build apk` с загрузкой артефакта, запуск на push и PR.
- README на английском: описание, Mermaid-схемы слоёв и потока данных, стек, запуск (fvm, build_runner, dart-define), тесты, ссылка на DECISIONS, roadmap, места под скриншоты и GIF и чек-лист съёмки.

## 6. Правила работы

- **Готово** означает: `dart format` без изменений, `flutter analyze --fatal-infos` даёт 0 замечаний, все тесты зелёные, CI зелёный, DECISIONS и LEARN обновлены.
- Коммиты по Conventional Commits на английском, один логический шаг на коммит, короткое сообщение.
- Конец фазы: стоп и отчёт на русском. В отчёте: что сделано и почему, 3–5 мест в коде, которые нужно понимать, 5 вопросов техлида. Всё это дописывается в `docs/LEARN.md`. Ты отвечаешь, я жёстко оцениваю и правлю.
- `docs/DECISIONS.md` на английском, потому что его будут читать ревьюеры. `PLAN.md` и `LEARN.md` на русском.
